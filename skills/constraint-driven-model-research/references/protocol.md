# 研究设置、基线与验证

确定研究设置时阅读；接续任务时只补变化与缺项。

## 先把比赛约束落到实现

读取赛题、规则、提交指南、数据字典、评价器及官方样例。把影响实现的规定记为“要求—来源—代码位置—待确认事项”，优先查清：

| 项目 | 需要确定的内容 |
| --- | --- |
| 研究范围 | 仅计划/分析，还是实际训练；本地实验与外部提交授权 |
| 目标 | 官方评分、主指标、保护指标、允许退化；用户另设目标时分开记录 |
| 数据 | 允许表/字段、发布日期与修订、外部数据许可、历史成员与缺失值 |
| 标签与时点 | 预测对象、决策时点、标签起止、可见性、允许回看总长度 |
| 验证 | 训练/选择/最终检查区间、滚动或扩展窗口、分组边界、已观察区间 |
| 评价 | 指标公式、聚合权重、样本过滤；交易任务还需成本、成交与组合约束 |
| 提交接口 | 入口、输入/输出结构、调用生命周期、历史不足处理、状态/在线更新规则 |
| 资源 | 截止时刻、次数单位、CPU/GPU/线程、时间/内存限制、外部机会 |

不要把样例注释、README笔误或本地习惯自动当成正式规则。文档、有效澄清与代码存在实质冲突时标明冲突；未解决前按已明确部分推进。外部评价口径未披露时如实记为未知，不把本地代理口径写成官方事实。

目标或口径缺失时集中澄清；继续检查材料、接口和不依赖缺项的基线步骤。普通本地实验在已有授权内执行。

## 建立与核对参照

1. 清点数据覆盖、日期/实体键、重复行、缺失与异常值；保留原始数据。
2. 在固定切分上运行官方训练与评价代码，保存完整配置、权重和预测。没有官方基线时，建立适配任务的简单模型。
3. 在新进程重载权重，走正式推理入口，核对输出并记录耗时与内存。
4. 用统一评价器得到参照值。无法复现官方数值时先核对日期、样本、标签、配置与依赖，保留差异原因。

官方基线、特征研究参照、当前最优模型和最终全量模型可以承担不同职责；按实际需要建立，不预设全部已存在。冻结比较参照时保存不可变配置与产物标识。已有可信年度/折权重可先重放；产物缺失、训练边界不明或任务要求重训时再拟合。

## 在搜索前设计验证

切分应模拟部署或隐藏评价的数据生成方式。时序任务使用向前切分；同实体重复观测或强关联样本按任务设置分组，不能用随机拆行制造容易的验证。

对评价开始时间 `v`，检查训练标签及其发布在 `v` 前已可用。金融标签可检查 `label_exit_time < v`，并按数据发布延迟收紧；仅按特征日期截断可能保留跨期标签。重叠标签需要按任务设置隔离边界。

预处理统计、编码、特征选择、监督表示及先验均在各折训练范围拟合。需要折外上游预测的堆叠模块使用 OOF 输入；不得把训练内预测冒充折外预测。最终全量模型的训练期回放与向前验证分开。

股票池和输入成员按当时可见信息构造。未来标签是否有效可以影响训练监督和事后指标，但不能反过来决定实时可见股票。回看按交易日期截断；使用历史表示时展开其上游特征窗口，核对整条依赖的总长度。

在可用数据内分出研究与最终检查区间，调参在研究部分完成。若数据有限无法保留独立检查集，说明限制，并用多时段表现、较少自由度和更严格的选择纪律降低风险。各折使用一致的候选配方，不针对困难折临时换规则。

固定日期、样本、费用、约束和评价器。条件变更后新建设置版本，并重算同条件参照。压力情景单列。被反复观察或用于选择的区间属于开发数据。

## 有限预算与最小记录

先定义预算单位，分别记录配置、拟合、评价折、预测/回放和外部提交。一次多折配置可能消耗多次训练；失败重试、多种子与最终拟合按本轮约定计入。

没有明确预算时提出有限的首批规模和停止点，用基线耗时估算；不默认无限运行。次数口径不明时明确采用的保守账法，不能据此扩大授权；仍影响可执行范围的歧义集中澄清。运行前预留全折确认、最终拟合与交付消耗，同时检查墙钟截止和并发总内存。

沿用简单 CSV、JSONL 或已有实验平台，每条运行至少可还原：

```text
trial_id / candidate_id / parent_id / settings_version
hypothesis / changed_parameters / complete_config_or_immutable_config_path
split_id / seed / train_range / max_train_label_available_time
stage / status / metrics / baseline_deltas / evaluation_sample_id
weights / predictions / logs / code_and_data_version
budget_units / elapsed_seconds / peak_memory / stop_or_failure_reason
```

计划、进行中、完成、失败、剪枝与复用分开；未测指标留空。保存失败和淘汰原因。上游权重、切分、标签、特征顺序或精度变化时使相关缓存失效。

接续已有任务时先核对当前目标、基线、最好结果、未完成工作和已用预算；“继续”不重置预算或增量起点。
